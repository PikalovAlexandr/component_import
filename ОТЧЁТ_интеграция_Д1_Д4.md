## Архитектурная находка: volume-mapping

После каждого `docker compose up -d --force-recreate partdb` **все правки в `/var/www/html` теряются** (контейнерный слой стирается). Файлы ComponentExt и 3 патча ядра не выживают. Решение — `docker-compose.override.yml` с volume-mounting изменённых каталогов/файлов с хоста:

```yaml
services:
  partdb:
    volumes:
      - /tmp/component_patched/src/Entity/ComponentExt:/var/www/html/src/Entity/ComponentExt:ro
      - /tmp/component_patched/src/Controller/ComponentExt:/var/www/html/src/Controller/ComponentExt:ro
      - /tmp/component_patched/src/State/ComponentExt:/var/www/html/src/State/ComponentExt:ro
      - /tmp/component_patched/templates/component_ext:/var/www/html/templates/component_ext:ro
      - /tmp/component_patched/src/Entity/Parts/Part.php:/var/www/html/src/Entity/Parts/Part.php:ro
      - /tmp/component_patched/src/Entity/Parts/PartLot.php:/var/www/html/src/Entity/Parts/PartLot.php:ro
      - /tmp/component_patched/src/Entity/PriceInformations/Orderdetail.php:/var/www/html/src/Entity/PriceInformations/Orderdetail.php:ro
```

После `force-recreate`:
- `composer dump-autoload` — обязателен (classmap кэшируется)
- `cache:clear` — обязателен (Doctrine metadata кэшируется)

## Приёмочные сценарии

### ПИ-3 (Д-3) — два kicad-api представления ✅

```
GET /ru/kicad-api/gost/v1/             → {"categories":"","parts":""}
GET /ru/kicad-api/iec/v1/              → {"categories":"","parts":""}

GET /ru/kicad-api/gost/v1/parts/1.json → symbolIdStr: 'K50-35:K50-35-100В-10'
GET /ru/kicad-api/iec/v1/parts/1.json  → symbolIdStr: 'K50-35-IEC:K50-35-100В-10'

(без роли IEC → symbolIdStr = штатный ГОСТ + поле «УГО: фолбэк: вариант «IEC» отсутствует»)
```
Backfill миграции: **308 ролей ГОСТ** из `eda_info_kicad_symbol`. Роль IEC добавляется через `POST /api/component_symbols` (имитация `component-project views`).

### ПИ-4 (Д-4) — очередь согласования ✅

Полный цикл через API:
```
1. draft → review:               200, деталь в очереди
2. очередь без паспорта:         gate_ready=false, passport=null
3. POST паспорт errors_count=0:  201
4. очередь с паспортом:          gate_ready=true, passport.errors_count=0
5. review → released:            200 (шлюз Д-2 пропустил)
6. очередь:                      0 деталей (ушла в released)
```
HTML-страница `/ru/component/review-queue`: 200, таблица с деталями, badges «нет паспорта»/«0 ошибок», кнопки «Выпустить» (disabled при `gate_ready=false`) и «Вернуть».
