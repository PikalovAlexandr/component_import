# Д-5: вложения (ТУ, SPICE) и уведомления — настройка без PHP-кода

Реализация Д-5 почти целиком легла на штатные механизмы + Python-инструмент
`component-attach` (пакет component_import >= 0.9.0). PHP-кода не требуется.

## Архитектура хранения (FR-4a)

Файлы (PDF ТУ, .lib/.mod SPICE, эталоны tu_*.yaml/csv) живут в **Gitea,
репозиторий `libraries/docs`** — это и есть версионирование документов.
В Part-DB создаются вложения-ССЫЛКИ на raw-URL Gitea:
- обычная ссылка `raw/main/...` — «актуальная редакция»;
- ссылка с коммитом `raw/<sha>/...` — иммутабельная версия, для деталей,
  замороженных в выпущенной КД.
Пара «PDF ТУ + эталонная таблица» лежит рядом в git
(`tu/OZh0464214.pdf` + `tu/OZh0464214.{yaml,csv}`) — требование «хранить
парой» ТЗ выполняется структурой репозитория.

## Команды

```bash
# ТУ -> вложение категории (один документ на серию):
component-attach tu --doc "ОЖ0.464.214 ТУ" --category K50-35 \
  --gitea http://сервер:3000 --repo docs --path tu/OZh0464214.pdf \
  --url http://сервер:90 --token <токен>

# SPICE-модель -> вложение детали + Sim.* параметры (группа SPICE):
component-attach spice --part K50-35-100В-10 --parts-lib <библиотека> \
  --sim Device=C --sim Type=elec --sim "Pins=1 2" \
  --gitea http://сервер:3000 --repo docs --path spice/k50-35.lib \
  --url http://сервер:90 --token <токен>
```
`--parts-lib` включает проверку **В-8** (Sim.Pins против выводов детали)
ДО выгрузки — модель с чужим выводом не уедет в базу.
Sim.* кладутся параметрами группы «SPICE» с EDA-видимостью -> KiCad получает
их в полях символа -> деталь из базы сразу пригодна к симуляции (FR-4b).

## Настройка Part-DB (один раз, UI)

1. Типы вложений «ТУ» и «SPICE» создаются автоматически при первом вызове
   component-attach; при желании — задать им иконки/ограничения в UI.
2. Проверить, что `defaultParameterVisibility` включена (уже сделано) —
   иначе Sim.* не доедут до KiCad.

## Уведомления (З-5)

- **Цены устарели**: cron на стенде —
  `0 8 * * 1 component-price status /opt/component/offers.json --max-age 90`
  (код возврата 1 -> любой алертинг: почта из cron, healthchecks и т.п.).
- **EOL/NRND**: штатные провайдеры Part-DB (Octopart) обновляют
  Manufacturing Status при синхронизации; включить после появления ключей
  Nexar (п.4 чек-листа М0). Поле уже отдаётся в KiCad-карточке
  («Manufacturing Status») — разработчик видит статус при выборе детали.
