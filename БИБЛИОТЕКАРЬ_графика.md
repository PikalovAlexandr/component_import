# Регламент библиотекаря: правка УГО и посадочных мест средствами KiCad

> Архитектура: графика — это файлы в git (Gitea `kicad-libs/{symbols,footprints,3dmodels}`).
> Part-DB хранит только ссылки (lib_id) и метаданные. Правка графики = правка
> файла в клоне; публикация = commit + push. Никаких отдельных «выгрузок графики
> в базу» не существует и не нужно.

## Рабочее место библиотекаря (уже готово)

```
~/component/graphics/symbols/     ← клон kicad-libs/symbols  (68 .kicad_sym)
~/component/graphics/footprints/  ← клон kicad-libs/footprints (67 серий .pretty)
```
Таблицы KiCad (`sym-lib-table`, `fp-lib-table`) указывают прямо в эти клоны:
правка и сохранение в KiCad меняют файлы клона. Push-токен уже вшит в remote.

## 1. Правка УГО (Symbol Editor)

1. KiCad → Eeschema → **Symbol Editor** (или иконка в менеджере).
2. Открыть библиотеку: `Device_GOST` (общие ГОСТ-УГО), `C_K10-17`, `K50-35`… (серии).
3. Выбрать символ, править графику, выводы (номер/имя/тип), поля.
4. **Сохранить в библиотеку** (иконка диска → «Save … in library»). Файл
   `<клон>/…/<Библиотека>.kicad_sym` изменён — база не тронута.

Масштаб эффекта:
- правка `Device_GOST:C` — **сотни деталей сразу** (унификация);
- правка `C_K10-17:XXX` — только эта серия.

## 2. Правка посадочных мест (Footprint Editor)

1. KiCad → Pcbnew → **Footprint Editor**.
2. Открыть библиотеку серии (`C_K10-17` и т.п.) → футпринт → правка (площадки,
   шелк, маска, courthouse).
3. **Save footprint in library** — меняется `.kicad_mod` в `<клон>/<серия>/<серия>.pretty/`.

3D-модель: править `.wrl` в клоне `3dmodels` (текстовый/внешний редактор);
привязка — строка `(model "${COMPONENT_3D}/<имя>.wrl")` внутри футпринта.

## 3. Публикация (обязательная последовательность)

```bash
cd ~/component/graphics/symbols      # или footprints
git pull                             # подтянуть чужие правки ДО начала работы

# … правка в KiCad …

# НОРМОКОНТРОЛЬ перед пушем (шлюз качества):
component-import --no-fix -o /tmp/chk ~/component/import_out/<СЕРИЯ>   # В-2..В-6, В-9
# для правок УГО при наличии пары ГОСТ/IEC:
component-project views <либ_гост>.kicad_sym <либ_iec>.kicad_sym -o /tmp/v --name <СЕРИЯ>  # В-1

git add -A
git commit -m "C_K10-17: исправлен шаг площадок XXX по ТУ"
git push                             # токен в remote — пароль не спросит
```

После push: на других рабочих местах `git pull` в их клонах
(или обновление скриптом по расписанию).

## 4. Правила (важно)

1. **Не переименовывать** символ/футпринт при правке: lib_id в Part-DB
   ссылается по имени. Переименование = отдельная операция:
   `tools/remap_footprints.py --field symbol|footprint` (PATCH eda_info /
   component_symbols) — до или после пуша, но одним согласованным изменением.
2. **Версии для замороженной КД**: у роли УГО есть `git_rev` (Д-3,
   `component_symbols.git_rev`) — SHA коммита. Новые разработки берут main
   («актуальная редакция»); для выпущенной КД библиотекарь пинит ревизию.
3. **Правило гигиены графики**: новые файлы в репо — только после
   `component-import --no-fix` (как делали с Device_GOST).
4. Изменение графики **не требует** правки Part-DB, если имена сохранены.

## 5. Вариант: GIT-тип библиотек (по желанию)

В KiCad 8+ официальных сборок в диалоге Manage Symbol/Footprint Libraries
есть тип **GIT** — KiCad сам тянет репозиторий и синхронизирует сохранения.
Можно перевести записи таблиц с локального клона на GIT-тип с URL
`http://<gitea>:3000/kicad-libs/symbols.git` — тогда шаги pull/push делает
KiCad (учётные данные — при первом обращении). Локальный клон остаётся
рабочим вариантом без зависимостей от версии KiCad.

## 6. Типовой цикл одним списком

правка в редакторе KiCad → `component-import --no-fix` (нормоконтроль) →
`git pull --rebase` → `git add … commit … push` → (при переименованиях —
remap в Part-DB) → уведомление разработчикам «git pull».
