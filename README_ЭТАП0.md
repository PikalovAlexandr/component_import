# Этап 0 — развёртывание и веха М0

Комплект: `docker-compose.yml`, `.env.example`, `scripts/` (backup/restore/update), `kicad/КОМПОНЕНТ.kicad_httplib`, `config/контракт_полей_eskd.csv`.

## 1. Установка (Linux-сервер, ≥4 ГБ ОЗУ, ≥50 ГБ диск)

```bash
sudo apt install docker.io docker-compose-v2      # или по официальной инструкции Docker
sudo mkdir -p /opt/component && cd /opt/component
# скопировать сюда содержимое комплекта
cp .env.example .env && nano .env                 # SERVER_HOST, пароль БД, ключи Nexar
docker compose up -d
docker compose logs -f partdb                     # дождаться завершения первичных миграций
```

Первый вход в Part-DB: `http://<сервер>:8080`, логин `admin`, пароль выводится в лог контейнера при первом запуске (`docker compose logs partdb | grep -i password`). Сразу сменить пароль, создать пользователей по ролям НФ-2 (библиотекарь, разработчик, закупщик — через группы прав Part-DB).

Gitea: `http://<сервер>:3000` — при первом входе завершить мастер установки, создать организацию `libraries` и репозитории `symbols`, `footprints`, `3dmodels`.

Бэкапы: `crontab -e` → `30 2 * * * /opt/component/scripts/backup.sh >> /var/log/component-backup.log 2>&1`. Сразу выполнить один бэкап вручную и один тестовый `restore.sh` на пустом стенде (норматив ПИ-8).

## 2. Подключение KiCad (у каждого разработчика)

1. В Part-DB: Настройки пользователя → API tokens → создать токен с правом чтения.
2. В файле `kicad/КОМПОНЕНТ.kicad_httplib` заменить адрес сервера и токен; раздать файл разработчикам.
3. KiCad 8/9: Preferences → Manage Symbol Libraries → Add → тип **HTTP**, путь к `.kicad_httplib`.
4. В Part-DB у категории на вкладке EDA включить видимость в KiCad и задать базовый символ/футпринт по умолчанию.

## 3. Чек-лист вехи М0 (все пункты = «да»)

| № | Проверка | Закрывает |
|---|---|---|
| 1 | Деталь, заведённая вручную в Part-DB (конденсатор из K50-35_fixed: символ+футпринт залиты в Gitea, поля из CSV-контракта), видна в диалоге «Add Symbol» KiCad | Р-1, FR-5 |
| 2 | Поля детали пришли в свойства символа в схеме; кириллица не искажена | НД-5 |
| 3 | Netlist проекта с этой деталью прогнан через eskd-templates v2.1 — перечень элементов собрался; список полей, которых не хватило/не совпали имена, внесён правками в `config/контракт_полей_eskd.csv` | Ц-3, О-5, риск №2 плана |
| 4 | Провайдер Octopart: поиск любого импортного MPN подтягивает цены и datasheet | З-3 |
| 5 | `backup.sh` + `restore.sh` на чистом стенде — система поднялась, деталь с вложением открывается | НД-2, ПИ-8 |
| 6 | **Проверка риска №1:** зафиксировать, какие поля KiCad HTTP API Part-DB отдаёт/не отдаёт (произвольные свойства? выбор символа на деталь?) — таблица «что доработать» для этапов 1–2. Особо: можно ли на одну деталь отдать два символа (ГОСТ/IEC) — ожидаемо НЕТ, это и есть доработка этапа 2 | риск №1 |

## 4. Параллельная работа библиотекаря

- Сверить `config/контракт_полей_eskd.csv` с проектом `example` из eskd-templates v2.1 (пункт 3 чек-листа) — это «контракт», по которому этап 1 будет маппить поля при импорте.
- Собрать примеры наименований с приёмкой «5» (конденсаторы, резисторы, микросхемы) — для шаблонов FR-4c.
- Загрузить в Part-DB первые документы: ТУ ОЖ0.464.214 (k50-35.pdf), РК415 — как вложения типа «ТУ» (пока на категорию; привязка к сущности Doc — этап 1).

## 5. Результат этапа

По завершении чек-листа М0 закрыта, главный технический риск оценён количественно, и можно запускать этап 1 (мастер импорта + валидаторы — прототип уже есть, переводится в сервис).
